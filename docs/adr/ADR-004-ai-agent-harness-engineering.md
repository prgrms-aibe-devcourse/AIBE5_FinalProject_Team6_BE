# ADR-004: 클로드 코드(Claude Code) 기반 AI 에이전트 하네스(Agent Harness) 엔지니어링 구축

| 항목 | 내용 |
| --- | --- |
| **상태** | Accepted |
| **결정일** | 2026-05-19 |
| **관련 문서** | [SHARED](../ai/SHARED.md) |

---

## Title

FANDROPS 프로젝트의 코드 품질 유지와 아키텍처 붕괴 방지를 위해, 단순한 AI 지시를 넘어 **시스템적으로 통제된 AI 협업 환경인 '에이전트 하네스(Agent Harness)'**를 구축한다.

---

## Context — 왜 이 결정이 필요한가

FANDROPS는 K-Pop 오픈런(핫딜) 트래픽 스파이크를 다루며 오버셀 0, 중복 결제 0을 증명해야 하는 고난도 B2B2C 커머스 프로젝트다.
5인 팀이 7주 안에 측정 가능한 결과를 내기 위해 AI 코딩 어시스턴트(Claude Code v2.1.83)를 적극 도입했으나, AI가 아키텍처 규칙(domain 레이어의 JPA 참조 금지 등)을 위반하거나 환각(Hallucination)을 일으킬 위험이 존재했다. 이를 방지하기 위해 AI가 '시니어 개발자의 사고방식'으로 자율 제어되도록 강제하는 시스템적 하네스가 필요했다.

---

## Decision — 결정 및 수행한 작업

우리는 클로드 코드의 최신 기능(Agent Teams, MCP, Hooks 등)을 활용하여 다음 4가지 계층의 하네스 엔지니어링을 구축했다.

### 1. 컨텍스트 분리와 YAML 프런트매터(Frontmatter)를 통한 에이전트 라우팅 (Agent Teams)
- 단일 프롬프트 대신, 공통 규칙(`SHARED.md`)과 5명의 도메인 전문가 페르소나(`pyojimin.md`, `hyungseongbin.md`, `jangseongjae.md`, `junghwancheol.md`, `jiyoungjae.md`)로 컨텍스트를 완벽히 분리했다.
- 각 페르소나 마크다운 파일 최상단에 13개의 YAML 프런트매터 필드를 하드코딩하여, `modules/payment/**` 등 특정 경로의 코드를 수정할 때 클로드 코드가 해당 도메인 전문가의 소유권(Ownership)을 강제 인식하도록 설정했다.

### 2. 고급 인지 프레임워크 주입 (Cognitive Harness)
`SHARED.md`에 AI의 행동 양식을 통제하는 메타 프롬프팅 기법을 주입했다.
- **Superpowers 워크플로우**: 코드를 작성하기 전 무조건 **'Brainstorm → Plan → Execute → Debug'**의 4단계를 거치도록 시스템 룰을 강제했다.
- **회의(Meeting) 모듈화**: 복잡한 아키텍처 결정 시 AI가 즉시 코딩하지 않고 SRE, 보안, 도메인 전문가 관점에서 서로 토론하여 가장 강한 반대 논리를 도출한 뒤 합의하게 만들었다.
- **사고 트리(ToT, Tree of Thoughts)**: 문제 해결 시 가능한 해결책을 여러 갈래로 탐색하고 스스로 장단점을 평가(self-evaluate)하도록 지침을 추가했다.

### 3. 도메인별 메타 템플릿과 시스템 훅(Hook) 연동
- 각 페르소나 파일에 도메인 특화 체크리스트를 강제했다 (예: 장성재 페르소나에 Saga 보상 트랜잭션 복구 템플릿, 지영재 페르소나에 P95 300ms 등 SLO 역검증 템플릿 추가).
- **시스템 훅 자동화**: 클로드 코드의 시스템 설정(`.claude/settings.json`)을 조작하여, 파일 수정 도구(Edit, Write)가 실행된 직후(PostToolUse) `concurrency-guard.py`가 트리거 되도록 구성했다. 이를 통해 형성빈 도메인(`modules/order/`, `modules/inventory/`) 수정 시 자동으로 k6 동시성 검증 체크리스트가 컨텍스트에 주입된다.

### 4. 글로벌 공통 룰 적용 (Kopitiam 대안)
- 클로드 코드 런타임의 보수적 검증 정책을 고려하여, `claude-kopitiam`의 7대 공통 규칙(보안 가드레일, 커밋 컨벤션 등)을 `~/.claude/CLAUDE.md` 단일 파일에 통합하여 매 세션 시스템 레벨에서 자동 로드되도록 구성했다.

---

## Consequences — 트레이드오프

### 긍정적 효과 (이점)
- **아키텍처 보호**: AI가 멀티모듈 모놀리스 규칙과 레이어별 제약(ADR-001, 002)을 스스로 인지하고 위반을 사전에 차단한다.
- **토큰 비용 및 환각 감소**: 필요한 페르소나와 SSOT(`SHARED.md`)만 명시적으로 끌어와 문맥을 최소화함으로써 처리 속도를 높이고 엉뚱한 코드를 짜는 것을 방지한다.
- **코드 품질 상향 평준화**: 모든 도메인 코드가 시니어 개발자의 검토(회의 모듈화, ToT)를 거친 것과 동일한 수준으로 작성된다.

### 부정적 효과 (트레이드오프 및 완화)
- **제한 사항**: 클로드 코드의 런타임 자체 방어 기제로 인해 SessionStart 훅을 통한 완전 자동 로딩이 불가하다.
- **완화**: 터미널에서 세션 시작 시 수동으로 `@docs/ai/SHARED.md` `@docs/ai/personas/<본인>.md`를 입력하도록 팀 규칙을 명문화했다.

## Compliance — 준수 방법

| # | 규칙 |
| --- | --- |
| 01 | 모든 개발자는 코딩을 시작하기 전 클로드 코드에 `@docs/ai/SHARED.md`와 본인 담당 페르소나를 반드시 로드해야 한다. |
| 02 | API 스펙, 상태 머신, ERD 등 아키텍처 문서(SSOT)가 변경되면 연관된 페르소나 파일(`*.md`)도 즉시 갱신(동기화)하여 AI의 컨텍스트를 최신으로 유지한다. |
| 03 | AI가 계획(Plan)을 제시하지 않고 바로 코드를 수정하려 할 경우, 조작을 중단시키고 워크플로우를 준수하도록 지시한다. |
