01 Tech Stack

Java 21 / Spring Boot 기반으로 구성한다. 아래 스택은 기획서(01~04) 및 정합성 설계 문서를 기준으로 도출한 것으로, 각 선택에는 왜 이 기술이어야 하는가에 대한 근거가 함께 명시된다.

Core
Language
Java 21 (LTS)
Virtual Thread(Project Loom)로 SSE·웹훅 등 I/O 블로킹 구간 처리 비용 최소화. 최신 LTS로 팀 기술 증명에 적합.
Framework
Spring Boot 3.x
Java 21 Virtual Thread 공식 지원. Spring Security, Data JPA, Actuator 생태계 그대로 활용.
Build
Gradle (Kotlin DSL)
멀티모듈 서브프로젝트 의존성 방향을 빌드 레벨에서 강제. 잘못된 모듈 참조는 컴파일 실패로 조기 차단. 자세한 사항은 ADR-002 참조.
API Style
REST (SpringMVC) + SSE
대기열 순번 실시간 전달(F08-01)에 SSE 사용. WebSocket 스케일·모더레이션 부담은 Not Scope.
Data
RDBMS
MySQL 8.x (AWS RDS)
주문·결제·재고 상태 정합성을 트랜잭션으로 보장. 동시성 제어를 위한 비관락(SELECT … FOR UPDATE) 및 단일 쿼리 원자적 업데이트(Atomic Update) 병용. 자세한 스키마는 ERD 설계 문서 참조.
ORM
Spring Data JPA + QueryDSL
커서 페이징·N+1 제어에 QueryDSL. JPA는 infrastructure 레이어에만 격리.
Cache / 분산락
Redis (AWS ElastiCache) + Redisson
핫딜 대기열 Sorted Set, 재고 분산락, 랭킹 집계, Read 캐시. Redisson으로 RLock 비교 실험(Phase 3). 대기열 상태 관리는 대기열 상태 머신 문서 참조.
Migration
Flyway
팀 멀티모듈 환경에서 스키마 변경 이력 버전 관리. 롤백 스크립트 강제.
Security · Auth · Traffic Control
인증
Spring Security + JWT
이메일·소셜(카카오·구글) 로그인(F01-01~02). Access/Refresh Token 분리. 인가는 모듈 레벨에서 처리.
소셜 로그인
Spring OAuth2 Client
카카오·구글 OAuth2 표준 흐름 처리. Spring Security와 통합.
Rate Limiting
Bucket4j (Redis 연동)
핫딜 오픈 구간 매크로·비정상 트래픽 방어(장성재 담당). Token Bucket 알고리즘을 사용하며, Redis 백엔드로 분산 환경 적용.
멱등성
Idempotency Key (custom)
결제 중복 요청 방어. PAYMENT.payment_key Unique Index 및 INVENTORY_HISTORY Unique Key 조합 연동. 웹훅 재전송 시나리오 완벽 대응.
결제 · 외부 연동
PG
토스페이먼츠
단일 PG로 깊게 — 멱등·웹훅·실패 복구에 리소스 집중. 웹훅 수신 멱등성 보장. 시퀀스 근거는 결제·주문 시퀀스 문서 참조.
알림
이메일 (JavaMailSender) + 추후 FCM
재입고·결제완료·라이브 알림 전송(표지민 담당). Kafka 없이 DB/내부 큐 및 Outbox 패턴으로 MVP 구현.
Observability · 인프라
모니터링
Prometheus + Grafana
Write P95 < 300ms, 5xx < 0.1% SLO 수치 증명. Spring Actuator → Prometheus exporter 연결.
부하 테스트
k6
핫딜 동시 ~1k 스파이크 시나리오 재현. 오버셀 0 검증, 락 전략 비교표 작성.
Cloud
AWS (EC2 · RDS · ElastiCache)
스테이징·프로덕션 분리. VPC 격리, 보안그룹 설계(지영재 담당).
CI/CD
GitHub Actions
PR머지 → 빌드·테스트·배포 파이프라인. 무중단 배포·롤백 검증.
Reverse Proxy
Nginx
SSL 종단, 라우팅, 정적 자산 서빙. 무중단 Blue/Green 전환.
API 문서
SpringDoc (Swagger/OpenAPI 3)
Phase 1에서 API Mock 계약 동결 후, 최종 확정판 자동 생성. API 스펙은 MVP API 명세 참조.
테스트
단위 테스트
JUnit 5 + Mockito
Domain 레이어 순수 단위 테스트. Spring 컨텍스트 없이 빠른 피드백.
통합 테스트
Testcontainers
MySQL·Redis 실제 컨테이너로 결제·재고 E2E 시나리오 검증. CI 환경에서 동일 재현.
아키텍처 검증
ArchUnit
Domain 레이어가 Spring·JPA를 import하면 테스트 실패. 의존성 규칙을 코드로 강제.

레이어 역할 정의
레이어역할규칙
*-api HTTP 요청 수신, DTO 변환, Application 호출 비즈니스 로직 없음. Controller만.
*-application 유스케이스 실행, 트랜잭션 경계, 여러 Domain 조합 포트(interface) 정의. 구현체 직접 참조 금지.
*-domain 핵심 비즈니스 규칙, Entity, Value Object Spring·JPA·Redis 의존 금지. 빌드로 강제.
*-infrastructure JPA Repository, Redis 클라이언트, 외부 API 어댑터 Application 포트 구현체. Domain은 참조하되 역방향 금지.
의존성 방향 규칙
✔ 허용
api → application → domain
infrastructure → domain
application → (port interface)
common → (모든 모듈)
✕ 금지
domain → Spring / JPA / Redis
user-* → order-infrastructure
order-api → payment-infrastructure
domain → domain (타 모듈 직접 참조)
검증 및 탐색 — ./gradlew :modules:order:order-domain:dependencies 로 Spring 누수 확인 가능. 자세한 의존성 구조 규칙은 아키텍처 규칙 상세 문서를 참고한다.
